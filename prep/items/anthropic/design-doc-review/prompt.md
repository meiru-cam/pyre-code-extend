The document below proposes a batching and load-balancing layer for a pool of GPU model servers. Each server holds one loaded model and executes requests in *batches*: a batch groups several requests into one call to the model, so the GPU does one pass of work instead of many. A server's batch call has a fixed contract that this review does not revisit — it is owned by a different team:

```py
def run_batch(requests: list[Request]) -> list[Response]:
    """Runs one inference batch on this server and blocks until it returns."""
```

- `1 <= len(requests) <= 50`; the call returns exactly one response per request, in the same order.
- The call takes a fixed **100 ms**, whether 1 or 50 of the 50 slots are filled.
- A server accepts one `run_batch` call at a time; a second call blocks until the first returns.
- The model itself is a black box behind this call: this review is about the system that queues, batches, and routes requests to it, not about anything that happens inside `run_batch`.
- Continuous or token-level batching, and any other change to this contract, are out of scope.
